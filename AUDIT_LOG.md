# Engineering Audit Log

## Original reference upgrade — 2026-11-02

The active renderer previously used the shared third-party low-poly chassis. It now loads **Formula Reference 26**, an original Formula-style design study generated by `scripts/build-reference-car.mjs`. The existing manifest, semantic inspection, geometry-aware flow provider, and CFD adapter remain in place.

### Asset and rendering changes

- Added indexed GLBs for Ultra (336,648 triangles / 8.55 MB), High (196,556 / 5.38 MB), and Medium/Low (113,898 / 3.49 MB). Each has the same semantic hierarchy and 56 material/component meshes.
- Authored curved and capped bodywork, layered cambered airfoils, sidepod openings, cooling louvres, floor fences, diffuser strakes, an open cockpit, halo, steering controls, wishbones, brake hardware, smooth tire shoulders, wheel covers, and original sidewall lettering.
- Declared all four wheel pivots and X spin axes. Each complete wheel assembly rotates once; suspension-mounted brake calipers remain fixed.
- Added independently modelled front/rear flap pivots. Motion angles are illustrative reference-design settings, not constructor mechanism measurements.
- Separated dielectric clearcoat paint, carbon micro-normal detail, rubber grain, metal, wheel covers, lettering, cockpit, and glass finishes. Opaque materials remain opaque outside X-ray view. Mirrors and the steering display use an opaque clearcoat finish rather than unnecessary transmission shading.
- Replaced the presentation plinth/grid with an epoxy-floor workshop, soft floor reflections, slab joints, studio softboxes, restrained equipment, and contact shadows. Static contact shadows stop updating after their settling frames.
- Added explicit AgX tone mapping to the HDR post-processing chain. The composer disables renderer tone mapping, so a renderer-only setting was insufficient. Direct rendering uses the same tone-mapping family.
- Corrected wheel-ground placement, side-view framing, manual-orbit retention, close-up field of view, portrait framing, and adaptive orbit distance limits.
- Kept model provenance available in a collapsible panel, with a persistent reference-design notice in the garage and a non-CFD notice in aero mode.

### Runtime architecture

Team colors update on the existing model instead of reloading shared geometry. Loading depends on the asset/mapping signature and selected LOD. Resource disposal occurs after the old primitive leaves the scene, avoiding a final-frame geometry re-upload.

The geometry-aware provider now receives one obstacle per semantic component rather than repeated material bounds. All four wheel bounds come first in the GPU's bounded obstacle list. This remains an AABB approximation, not surface collision or CFD.

### Accuracy and licensing

The original vehicle geometry is CC0. Helvetiker lettering retains the MAGENTA font notice in `public/assets/cars/reference-26/LICENSE.txt`. The unused legacy model and its CC-BY-4.0 attribution remain intact.

All team colorways share one original design. No constructor CAD, exact 2026 compliance, constructor-specific aerodynamic performance, or measured active-aero mechanisms are claimed. No CFD dataset is bundled. The existing adapter continues to validate external datasets and fall back to the geometry-aware provider.

### Verification

`npm run verify` passes strict TypeScript, all 24 tests, ESLint, and the production Vite build. New asset tests load the actual GLBs and validate their triangle budget, width, wheelbase, semantic mappings, wheel pivots, explicit spin axes, and all LODs. Legacy provenance, manifest rejection, CFD adapter, provider, and zero-speed invariant tests remain enabled.

A Chrome/Playwright runtime pass inspected rendered pixels for all camera presets, cycled all 11 colorways without model requests, checked manual-orbit retention, exercised wind-tunnel startup, Straight Mode, exploded and X-ray views, and checked 320, 768, 1024 and 1440 px layouts without horizontal page overflow. The pass captured 27 screenshot/state records with zero console errors or failed network requests. Local evidence is in `.tmp-audit/realism/matrix-report.json` and the adjacent PNGs; these temporary QA files are not source assets.

The follow-up quality pass exercised High → Ultra → Medium → Low → High and verified zero-speed controls. Removing unnecessary car-glass transmission increased the local High-mode hero samples to about 33–35 FPS; Medium/Low reached about 60 FPS and Ultra about 16 FPS on this Intel UHD machine at 1600 × 1000. Earlier tunnel samples were about 26 FPS and the heavy combined tunnel/X-ray view about 5 FPS. These are development point samples under local QA load, not a controlled production benchmark. Stable 60 FPS across devices is not claimed.

The quality pass rendered every preset successfully. Intel's D3D shader compiler emitted one non-fatal X3595 diagnostic about gradients in a varying loop while the Ultra post-processing shaders compiled. This remains a GPU/backend compatibility warning; it is retained in `.tmp-audit/realism/quality-report.json`, not suppressed. No JavaScript exception or failed shader link was observed.

### Remaining visual limits

This is a procedural reference design with procedural surface detail. Authored UV/PBR texture sets, more detailed mechanical interiors, and licensed constructor geometry would improve close-up photorealism further. The geometry-aware flow is qualitative and uses component bounds; it does not resolve the actual tire/body surfaces or produce surface Cp.
